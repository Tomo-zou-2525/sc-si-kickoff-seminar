# pathos

ループエンジニアリングの重要性を言及したい

独善的になりがちなAI開発において、俯瞰的な観点をプロジェクトにもたらす有効な手法となり得るため、AIと共にクリエイティブを行うためには必須な要素と感じる

AIはインプットに対して、基本的に否定的な意見を言わない傾向にある
また、attentionの仕組みとして、デフォルトの動作で全く同じ回答が返ってくることもない

これでは、インプットの精査を行おうと思っても比較対象のサンプルを確保することも難しく、結果としてシングルプロセス的なプロンプトエンジニアリングに終始してしまうと考える

そこで、ループエンジニアリング、かつHOITを意識することで、人間の役割をループの構築、監視に注力できるようになり、結果として目的達成にイノセンスな手段を構築できるのではないだろうか

もちろん、これは人間側が論理的に目的達成を見据え、その評価ができる前提ではある。

そのためには、定義には「決して」曖昧な表現を使わない、ということが肝要であろう

決定する

実行する

検討する

ではない、もう一歩も二歩も踏み込んだ言語化が必要なのである

・インプット①との乖離点
ADRがあればHarnessは実装できるのではないか？
-> 明確に異なると考える

これはツールやソフトウェアの使用ではなく、LLM,GPT（Generative Pre-training Transformer）の特徴である

受け取ったプロンプト・データに対し、事前学習モデルによって推論が行われ、Attensionにて幾重にも渡る統計的なアウトプットが作成される
そのパラメータは天文学的な数に及び、全く同じ動作を保証する、といった仕様では、そもそも異なるのである（このあたりは理解が曖昧なのでレビューしてほしい）

なので、ADRを用意する、をれに加えて、
- ルール
- チェック
- 実行制御

を、Harnessに組み込むべきである

より平易に表現すると

- AIが守るべきルールを定める
- AIの動き方がルールに沿っているかを判定する
- AIのアウトプットがルールに基づいて実行されているかを確認する

である

これを、同社は三権分立になぞらえ

- ルール:立法
- チェック（検証）：司法
- 実行制御：行政

と定めた

Harnessは汎用的なものであるべきであり、これは行政の役割を担う

逆に、立法や司法に関しては、人間が策定・改修を行うべきである
（AIの力を借りてルールを策定するにしても、決定権は人間が持つべきである、という考え）

# インプットの総評③

https://www.youtube.com/watch?v=K6KX41tLH2s

loop engineeringへの言及である

AIの使い方を4段階で整理し、これから目指すべき方向性はloop engineeringであることを説いている

まず、4段階の説明として

1. prompt engineering -> AIに入力するデータを工夫することで、より高い精度で回答を得よう、という手法
2. context engineering -> LLMが参照させるデータを管理し、専門的なドメイン知識を付与した状態で精度の高い回答を得る
3. Harness engineering -> AIが自律して稼働できる環境を設計・構築する
4. 人間がワークフローから脱し、より目的達成に必要なタスクに集中する

今回の資料では、この4. の項目に言及している

具体的には

Loopには3層を設けて

1層目はエージェント型コーディングループ
主にAIが実装〜テストを行う

2層目は開発者フィードバックループ
AIの成果物を人間が評価、方向づけを行う

3層目は外部フィードバックループ
第2層までの成果物を外部の人間に評価、方針を更新する

つまり、人間は、人間しか知り得ないコンテキストを整理・共有する役割を担う

ループの設計とは
	全てAIに任せるのではない
	全て人間がやるのでもない
	3層構造のうち、どこに人間のインプットを置くのかを決める
