# ADR 0001: セミナースライドのデザインシステムと Slidev 採用

- ステータス: Accepted
- 日付: 2026-08-30

## コンテキスト

SC×AI キックオフセミナーのスライドを作成している。`presentation-templates.md`（動画「誰でも見やすい資料がつくれる7つのコツ」の原則をまとめたもの）をデザインの拠り所として採用したい。このテンプレートは **Marp 前提** で書かれているが、既存の本番スライド（`slides/slides.md`）は **Slidev** で構築済みだった。

決めるべきこと:

1. どのスライドツールで本番を進めるか（Marp か Slidev か）
2. テンプレートのデザイン原則をどう本番へ適用するか
3. 適用時に発生したビルドエラーへの恒久対応

## 決定

### 1. ツールは Slidev に統一する

- 本番 `slides.md` が既に Slidev で書かれており、`v-click`・`layout: section`・UnoCSS など Slidev 固有機能を利用済み。
- 比較のため Marp 版（`template-samples.md`）と Slidev 版（`template-samples-slidev.md`）のテンプレートサンプルを両方作成し、見比べた上で Slidev を採用。
- Marp 版は参考として残す。

### 2. デザインシステムは `style:` フロントマターで一元適用する

テンプレートの原則を、各スライドに個別記述するのではなく `slides.md` 先頭の `style:` ブロックに集約する。適用する原則:

- フォント: 游ゴシック系（明朝体は使わない）
- 背景: 白 `#ffffff` / 本文: `#333333`（真っ黒は使わない）
- 強調・見出し: メインカラー `#0b2f64` の 1 色のみ
- リンクの下線を消す（強調は太字で表現）
- 図形は角丸・塗りつぶし・影なし（`.bordered-box`）、数字は Helvetica（`.large-number`）

内容（構成・文言）には手を入れず、見た目のルールだけを揃える方針とした。

### 3. Slidev のパース制約を回避するルールを設ける

適用時、`slidev build` が `Attribute name cannot start with '='` および `Element is missing end tag` で失敗した。原因と恒久対応:

- `style:` ブロック内の CSS コメント `/* */` を禁止 → パースが崩れる
- YAML コメント（`#` 行）に `---` を含めない → フロントマター区切りと誤検出される
- HTML タグ内の Markdown 記法（`**太字**`）を禁止 → 展開されずビルドも崩れる
- HTML 要素の属性を複数行に分けない
- `<h1>` 直後の `->` は全角 `→` にする
- `<div>` の開閉を揃える

これらは再発しやすいため、スキル `slidev-frontmatter-safety`（`.kiro/skills/`）として別途ドキュメント化した。

## 影響

- 本番 `slides.md` はビルドが通る状態になった（既存の閉じタグ不整合・`->` 誤認も修正済み）。
- 今後スタイルを追記する際は `style:` 内で CSS コメントを使えない制約がある。意図はフロントマター外の `#` コメントに書く。
- テンプレート Slidev 版はサンプル画像が未配置のため、`slidev build`（静的書き出し）では未解決インポートになる。`npm run dev` でのプレビューには影響しない。

## 代替案

- **Marp に統一する**: テンプレートがそのまま使えるが、本番の Slidev 資産（`v-click` 等）を作り直す必要があり不採用。
- **デザインを各スライドに直書きする**: 一元管理できず保守しづらいため不採用。
